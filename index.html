JetBrains IDEs

The LumaBrowser plugin adds a Luma tool window to WebStorm, IntelliJ IDEA, PyCharm, Rider, GoLand and the other JetBrains IDEs: the Code agent works on the open project with your local models, and edits land in the editor. Installing copies the plugin into each IDE found on this machine; restart the IDE afterwards.

Install everywhere Adds the plugin to every IDE listed above.

VS Code

The LumaBrowser extension adds a Luma view to VS Code, VS Code Insiders, VSCodium, Cursor and Windsurf: the same Code agent and the same chat as the JetBrains plugin, working on the open folder with your local models. Installing runs the editor's own extension installer for each editor found on this machine; reload the editor window afterwards.

Install everywhere Adds the extension to every editor listed above.

Windhawk

Windhawk mods that bring Luma into Windows: notifications into the Hub, the Hub glance on the taskbar clock, Ask Luma in every window menu, Edge-forced links opened in Luma, and a Luma submenu in Explorer. They talk to Settings > Desktop Integration. Installing compiles the mod with Windhawk's own compiler and registers it as a local mod; Windows asks for administrator approval once per click.

Install every mod Adds every mod above except the Desktop Ping test mod, with one administrator prompt.

API security

Who can reach the REST API and MCP endpoints. Network mode and API keys are independent: combine them for stricter access.

Network mode Which addresses may call the API.
Any device that can reach this computer can drive the browser and read its data through the API. Turn on "Require API key" below or pick a narrower mode.
Allowed IPs Plain IPs and CIDR ranges, IPv4 and IPv6.
Require API key Every request must carry a valid key.
API keys Send the key as Authorization: Bearer <key> or as an X-Api-Key header. External MCP clients must set the LUMA_API_KEY environment variable.
Copy this key now. It is shown masked from here on; use Reveal on a key to see it again.
