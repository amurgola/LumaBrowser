# LumaBrowser for VS Code

The LumaBrowser Code agent inside VS Code, and the editors built on it (VS Code Insiders, VSCodium, Cursor, Windsurf).

Open the **Luma** view in the activity bar and the agent works on the folder you have open, with the local models, tools and agents you set up in LumaBrowser. Ask about the selection, add files to the chat, let it read, search, edit and run commands with your approval, and review each edit in the diff editor. In Source Control, **Generate Commit Message with Luma** drafts a concise message from the staged changes. Every session is a Code conversation in LumaBrowser too, so you can pick it up in the app or from the `luma` terminal command.

Requires LumaBrowser on the same machine (the extension starts it when it is not running).

## How it fits

The extension is a thin shell, the same one as the JetBrains plugin (`ide/jetbrains`). LumaBrowser does the work: model loading and hotswap, tool execution, file safety, approvals, compaction, history. The editor side owns the socket, the editor, files and notifications, and a webview renders the conversation.

```
VS Code ──WebSocket──▶  LumaBrowser  /api/ext/code-mode/terminal   (extensions/code-mode/terminal/TerminalBridge.js)
 │ hello { cwd: <folder>, origin: 'ide', client: 'vscode/Visual Studio Code 1.93.0' }
 │ prompt { text, context: [{ path, startLine, endLine, text }] }
 │ commit-message { requestId, diff, files, hint }
 ◀ delta / reasoning-delta / status / tool / command:output / done / error / suggest / commit-message-result …
```

Three things are shared rather than re-implemented, so the terminal, JetBrains and VS Code cannot drift apart:

| Shared | Source | Lands in |
|---|---|---|
| The page (markup, styles, the whole conversation renderer as ES modules, bundled with the app's markdown modules into one `app.js`) | `ide/webview/`, `core/llm-server/ui/js/markdown/` | `media/` |
| The tool-row grammar | `cli/lib/tui/ToolGrammar.js` | `media/shared/tool-grammar.js` |
| Discovery (handshake file, starting the app) and the WebSocket client | `cli/lib/connect/` (AppDiscovery, BridgeConnector and what they require) | `lib/connect/` |

`media/` and `lib/` are generated by the build and gitignored. Edit the sources, never the copies.

## Layout

| Path | What |
|---|---|
| `extension.js` | the entry VS Code loads: `activate` hands the work to `src/LumaExtension.js` |
| `src/LumaExtension.js` | activation: the session, the view, the status bar, commands, editor hooks |
| `src/LumaSession.js` | the per-window session (a port of `LumaSession.kt`); no `vscode` import, so it runs under jest |
| `src/LumaViewProvider.js`, `src/WebviewHtml.js` | the webview host, and how `index.html`'s placeholders become CSP-safe tags |
| `src/FileSync.js`, `src/EditorContext.js` | pre-write snapshots, the diff editor, open / insert; context chips |
| `src/CommitMessageCommand.js`, `src/GitChangeSet.js` | Generate Commit Message (VS Code's git API) |
| `src/AppExecutableLocator.js` | where LumaBrowser is installed |
| `src/CliConnectLib.js` | the CLI's discovery and socket (from `lib/`) in the session's shape |
| `resources/` | `host.js` (the page's host contract over the webview channel), `vscode.css` (theme tokens), the icon |

## Building

From the app repo root:

```
npm run build:vscode
```

`scripts/build-vscode-extension.js` (`tools/ide/VscodeExtensionBuilder.js`) syncs `media/` and `lib/`, stamps the app's version, and writes `ide/dist/luma-vscode.vsix`. The extension is plain JavaScript with no dependencies, so there is no `npm install`, bundler or `vsce` step. electron-builder ships `ide/dist` as `resources/ide`, the Windows installer offers to install it into every editor it finds, and Settings → General → VS Code does the same at runtime on every platform (both run the editor's own `code --install-extension`).

To debug: `npm run build:vscode -- --skip` (sync only), open `ide/vscode` in VS Code and press F5. `LUMA_DEV_OPEN=1` opens the view on start.

## Shortcuts

| Keys | Action |
|---|---|
| Ctrl+Alt+L | Ask Luma about the selection (or the current file) |
| Ctrl+Alt+Shift+L | Add the selection to the chat without sending |
| Escape (in the Luma view) | Stop the running turn |

The JetBrains plugin uses Ctrl+Shift+L for the first one; VS Code already binds that to "Select All Occurrences", so the extension uses Ctrl+Alt+L instead.
